# M4 — Recherche guidée Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search drops the system IME for an in-app D-pad keyboard on the left, and shows on the right the typed query, Chaîne-group and Genre chips, a highlighted best result and a 4-column poster grid. Search runs from 1 character, filters alone list Programmes, and the whole state (query, filters, results, scroll, exact focus) comes back after a Programme page.

**Architecture:** Pure logic in `app.ui.SearchModel.kt`:
- `SearchKeyboard` (layout, edit operations),
- `SearchHits` (per-Chaîne outcomes of one query; filter-then-fuse, failure),
- `BestResult` (exact/prefix rule on the normalized title),
- `SearchViews.of(...)` (what the right column shows: best, grid, status),
- focus keys and `SearchUiState.initialFocus()` / `rightEntry()` (pure, testable).

`SearchFusion.search` returns `SearchHits` instead of fused shows, so a Chaîne filter applies **before** the title fusion (same rule as « Tout voir »: a group keeps its own copy of a Programme another group also lists). Empty query + active filter reads the cache through `CatalogStore.browse(channelIds, genre?)` (`GenreGrid.arrange` with an optional Genre: recency, then title). TF1's remote `searchPrograms` fallback keeps a ≥ 3 characters guard inside `Tf1Provider`.

The Search screen is a `Box`: the keyboard (`Column` of `Row`s, never lazy) at 104 dp, the right column as one `TvLazyVerticalGrid` (4 columns) whose first items are full-span (query, chip rows, best result, status). Chips reuse the « Tout voir » chip (`FilterChip`, made internal; no behaviour change), posters reuse `PosterCaptionCard` (gains an optional `modifier`).

**Tech Stack:** Kotlin, Compose for TV (tv-foundation `TvLazyVerticalGrid`), Room, JUnit4 + Truth.

**Spec:** ROADMAP §M4 (grilling 2026-11-07, « Recherche »; « Recherche guidée »), SPEC §Recherche, DESIGN.md (Search, Tout voir, Focus targets, Failure states), lead brief decisions 1–8.

## D-pad map (decided)

- Initial focus: « A », or the restored focus key.
- Keyboard: 6 × 6 characters (A–Z, 0–9), then « Espace » (3 columns) and « Effacer » (3 columns). OK types; « Effacer » deletes one character.
- RIGHT from the last keyboard column (F, L, R, X, 3, 9, Effacer) enters the right column on: the element focused there last, if the query has not changed since and it is still shown; else the best result's first button; else the first poster; else « Réessayer » when every Provider failed; else the selected Chaîne chip. Rationale: after typing, the viewer wants the results; the chips sit one UP away.
- LEFT from the first element of a right-column row (first chip of each row, the best result's first button, the first poster of a grid row) returns to the key focused last.
- Back from the right column returns to the key focused last; Back from the keyboard leaves Search.
- DOWN: Chaîne chips → Genre chips → best result → grid (DOWN from the best result lands on the first poster).

## Review Focus

1. Keyboard layout and edits (no leading/double space, max length). `SearchKeyboardTest`.
2. Best result: exact or prefix of the normalized query, top-ranked only, not repeated in the grid. `BestResultTest`.
3. Filter-then-fuse by Chaîne group and Genre; all Providers failing = « Recherche indisponible. ». `SearchHitsTest`, `SearchFusionTest`.
4. Empty query: hint without filter, cached grid with a filter. `SearchViewsTest`, `CatalogBrowseTest`.
5. Focus restore and RIGHT entry. `SearchStateTest`.
6. TF1 remote fallback guarded at 3 characters, zero network. `Tf1RemoteSearchGuardTest`.
